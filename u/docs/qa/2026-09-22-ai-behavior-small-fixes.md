# Невеликі зміни поведінки AI

22 вересня 2026. Локальна реалізація за результатами архітектурного аналізу. Без розгортання на production.

## Що змінено

- У core та описі інструмента контенту узгоджено правило фактів: посилання на матеріали, Flexible і раніше згенерований текст не підтверджують вихід релізу. За невідомого статусу — нейтральний текст; явно повідомлений клієнтом статус можна використовувати.
- Після делегування рекомендовано спільний текст за замовчуванням. Прибрано обов'язкове повторне питання «однаково чи окремо» та вимогу збирати необов'язкові теги й побажання. Збережено інструкцію поважати контент для окремих сторінок.
- `add_campaign_content` повертає `campaignStage: draft` та `nextAction: review_content`; `finalize_campaign_draft` — `draft` та `review_before_checkout`. Уточнено різницю між збереженням, переглядом, оплатою й запуском. Умови readiness не змінено.
- Пошук повертає `recommendationBasis`: greedy, метрика аудиторії, відсутність гарантії оптимуму й прогнозу результативності. Модель отримує `followers` і `selectionOrder` замість оманливих `reach`, `best_value`, `max_reach` у пакетах. API для UI та збережений working state залишили попередні поля сумісності.
- Уточнено адаптивний збір брифу й прибрано суперечність між коротким підсумком бюджету та забороною повторювати всю збережену форму.

Не додано нових агентів, викликів моделі, таблиць/колекцій чи бізнес-станів. Алгоритм підбору, ціни, платежі, збереження пам'яті та навчання на кампаніях не змінено.

## Перевірка

Фінальна версія: **20 наборів / 200 тестів пройшли**, `npm run build` завершився успішно. Команда тестів: `npm test -- --runInBand src/modules/ai-agent src/modules/profile/services/profile-agent-search.spec.ts`.

Модульні тести перевіряють контракт наступних дій, неповний контент, незмінність результатів підбору, країни/Worldwide, відсутність псевдоохоплення та суперлативних назв у контексті моделі при збереженні сумісності UI й working state. Нові перевірки контрактів спочатку падали на попередній реалізації.

Розширено `SoundInfluencers-server/scripts/simulate-lazy-client.ts`: дев'ять повідомлень лінивого клієнта, делегування, матеріали без статусу релізу, зменшення бюджету зі 100 до 80 EUR, заборона самовільно міняти сторінки, погоджена заміна зі збереженням матеріалів, перегляд перед оплатою та явне підтвердження виходу треку. Перевіряється і відповідь, і фактично збережений текст.

Перший живий прогін виявив повторне твердження про найбільшу сумарну аудиторію. Другий — формулювання «найбільші доступні сторінки» та нечітке «оформлення» замість явного наступного кроку оплати. Ці випадки використано для уточнення інструкцій, нейтрального представлення пакетів моделі й розширення перевірки. Попередні записи збережено, невдалі результати не приховано.

Фінальна жива симуляція: **9 повідомлень, 16/16 перевірок пройшли**, код завершення 0. Невідомий статус релізу не став фактом у збереженому тексті; явне повідомлення клієнта про вихід релізу коректно потрапило до оновленого тексту. До дозволу на заміну залишилися попередні сторінки й матеріали; після дозволу — пакет €79 при ліміті €80 з матеріалами для обох сторінок. На кроці перегляду відповідь прямо назвала перехід до оплати через Proceed to checkout. У фінальних рекомендаціях не було тверджень про математичний максимум чи найбільші доступні сторінки.

## Межі перевірки

Симуляція використовує справжню налаштовану модель, синтетичний каталог і записи лише в оперативній пам'яті. До Mongo/Redis чи реальних кампаній не підключається. Перевіряється locked core із вбудованою рольовою інструкцією; активний production override з адмінки не перевірено.

Автоматичні перевірки формулювань — вузькі регресійні шаблони, а не доказ відсутності будь-яких вигадок. Повні відповіді та збережений контент також переглянуто вручну. Навіть у фінальному прогоні AI запитав кілька пунктів брифу одразу, попри прохання клієнта вести його. Після явного делегування на кроці контенту він уже просив лише матеріали. Загальну манеру першого знайомства не слід видавати за повністю виправлену.
